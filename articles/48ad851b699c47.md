## こんなことありませんか？

- ChatGPTに相談するたび、研究テーマを一から説明している
- Deep Researchの結果がブラウザのタブに埋もれて、次の調査で使えない
- 論文メモ、AIとの会話履歴、調査結果が別々の場所に散らばっている
- 「前に調べたあれ」を参照したいのに、過去の会話を探し回る
- 毎回同じ背景説明をコピペしている自分に気づく

AIツールは便利だが、**コンテキストが散らばると、結局また一から説明し直し**になる。
そこで、Claude Codeのエージェントでコンテキストを一括管理する仕組み「[research-with-AI-on-your-shoulder](https://github.com/nakano1122/research-with-AI-on-your-shoulder)」を作ってみた。

## 導入するとどうなる？

🔴 **Before**: 「○○の最新動向を調べよう」→ arXivを開く → キーワードを考える → 検索 → 別のキーワードで再検索 → 論文を開く → 読む → メモを取る → 次の論文...

🟢 **After**: 「○○の最新動向を調べて」→ ☕ コーヒーを淹れて戻ってくる → 調査結果がMarkdownで整理されている

- 「調べて」と言うだけで、**3つのエージェントが並列で論文を検索**
- 「この論文読みたい」と言うだけで、**PDFがMarkdownに変換され、要約が生成**
- 「次何すればいい？」と聞くだけで、**研究の進捗を分析してアクション提案**

指示を出すだけで、AIが適切なツールを選んで実行する。

## このシステムの強み

**1. 話しかけるだけで、適切なエージェントが自動選択される**

`/research-partner` に「関連研究を調べたい」と伝えるだけでよい。統括エージェントが意図を読み取り、最適な専門スキルを選んで実行する。

**2. 複数エージェントが並列で動作し、調査を高速化する**

論文調査では、3つのエージェントが異なる切り口で同時に検索を行う。人間が順番に調べるより速く、網羅的に情報を集められる。

![アーキテクチャ概要](/images/architecture-overview.png)
_統括エージェントが各スキルに作業を委譲し、並列実行する。_

## システム概要: 統括エージェントと専門スキル

**1つの統括エージェント**と**8つの専門スキル**で構成されている。

直接呼び出すのは `/research-partner`（統括エージェント）だけでよい。対話から意図を読み取り、適切な専門スキルを選択・実行する。

```
ユーザー: 「最近の推薦システムの動向を調べたい」
    ↓
/research-partner が意図を解釈
    ↓
/survey-broad を自動選択・実行
```

| スキル             | 役割                    | 自動選択の例                                |
| ------------------ | ----------------------- | ------------------------------------------- |
| `/survey-broad`    | 広範囲の並列論文調査    | 「動向を調べたい」「サーベイしたい」        |
| `/survey-focused`  | 特定テーマの深い調査    | 「○○について詳しく」                        |
| `/related-work`    | 先行研究の発見          | 「似た研究はある？」                        |
| `/pdf-to-markdown` | 論文PDFをMarkdownに変換 | 「この論文を読みたい」                      |
| `/paper-reader`    | 論文の要約・解説・Q&A   | 「要約して」「ここの意味は？」              |
| `/idea-organizer`  | アイデアの構造化・図解  | 「考えを整理したい」                        |
| `/next-action`     | 次のアクション提案      | 「次に何をすべき？」                        |
| `/codex-task`      | Codex CLIワーカー起動   | （Claude Codeが得意としない処理をする場合） |

## 技術的特徴1: マルチエージェント並列調査

![並列調査のフロー](/images/parallel-agents.png)
_複数のエージェントが異なるクエリで並列に検索し、結果を統合する。_

論文調査では、キーワードを変えながら何度も検索を繰り返すことになる。このシステムでは、**3つのエージェントが同時に異なる切り口で検索**する。

```
Agent 1: 主要キーワード × 年度で検索
Agent 2: 関連分野 × 手法で検索
Agent 3: 応用領域 × 問題設定で検索

→ 3つの結果を統合・重複排除・関連度順ソート
```

**効率的で網羅的な調査**ができる。Claude Codeの並列エージェント機能で、各エージェントは独立したプロセスで同時に動作する。

arXiv MCPとAcademic Search MCPを活用し、arXivやSemantic Scholarへ直接アクセスできる。調査結果は`content/daily/`に自動保存され、次回の調査にも活用される。

## 技術的特徴2: コンテキストの維持

`content/`ディレクトリは3つのフォルダで構成される。

```
content/
├── themes/      # 研究テーマ定義
├── daily/       # 日次メモ・調査結果
└── papers/      # 論文管理
```

**themes/**: 研究テーマ定義を置く場所。キーワードや研究課題を書いておくことで、AIが研究領域を理解する土台になる。

**daily/**: `YYYY-MM-DD_{タイトル}/memo.md`形式で日々のメモを管理。手書きメモとAI生成コンテンツが時系列で蓄積される。

**papers/**: 論文ごとにPDF、Markdown、読書ノートをまとめて管理。`reading-list.md`で進捗を確認できる。

エージェントは`themes/`と`daily/`からユーザーの関心を把握して応答する。

## 技術的特徴3: 実装時の工夫

**PDF→Markdownでページ画像を活用**

`pdftoppm`でページごとにPNG画像を生成し、エージェントが図表をそのままMarkdownに挿入する。論文の視覚的な構造を保った読書ノートを作成できる。

**Claude Code × Codex CLIのハイブリッド構成**

複雑な推論や判断はClaude Codeが担当し、ルーチン的な処理はCodex CLIに委譲する。Claude Codeが全体を統括し、Codex CLIが高速・低コストに実行する。

```
Claude Code (Orchestrator) → Agent → Codex CLI (Worker)
```

**テンプレート駆動の一貫性**

論文ノート、テーマ定義、日次メモにテンプレートを用意し、構造を標準化した。AIが一貫した形式で参照でき、理解精度が上がる。

## 実際の使用例

![研究ワークフロー](/images/workflow.png)
_典型的な研究ワークフロー。各ステップの成果物がcontent/に蓄積され、次回以降の調査に活用される。_

1. `/research-partner`で研究相談を開始
2. エージェントが`content/themes/`と`content/daily/`から現状を把握
3. `/survey-broad`で並列論文調査を実行
4. `/pdf-to-markdown`と`/paper-reader`で論文を精読
5. `/idea-organizer`でアイデアを構造化
6. `/next-action`で次のアクションを取得

各スキルは単独でも、`/research-partner`経由でも呼び出せる。

## まとめ

「論文を調べたい」「アイデアを整理したい」と伝えるだけで、システムが適切なエージェントを選び、結果を整理して返す。

コンテキストが散らばる問題を解決し、AIを研究のパートナーとして活用できる基盤を作った。
