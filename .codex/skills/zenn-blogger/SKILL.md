## 成果

読者が題材の価値と適用条件を短時間で判断でき、根拠をたどれる日本語の技術記事にする。記事の魅力は誇張ではなく、具体性と検証可能性でつくる。

## 執筆の進め方

1. 読者、解決する課題、記事で扱わない範囲を定める。結論または持ち帰れる判断を先に置く。
2. 仕様・API・数値・製品の現行動作などの事実は、一次情報（公式ドキュメント、仕様、一次発表）で確認する。時間に依存する内容は確認日を意識し、本文では必要な箇所に直接リンクを付ける。
3. 主張を「事実」「実践上の解釈」「筆者の判断」に分ける。根拠のない一般化や、出典のない比較はしない。
4. 複数のアプローチが成り立つ場合は、各案の向く条件・利点・制約を説明する。一つを正解として他を退けるのではなく、読者が選べる材料を示す。
5. Zenn の Front Matter を含む Markdown として `articles/` に保存し、`npm run lint` で確認する。

## 文体

- 短く具体的に書く。煽り、過剰な導入、冗長な比喩、根拠のない「必須」「最適」は使わない。
- 導入で課題と結論を示し、本文ではコード、設定例、判断基準、失敗しやすい点を必要な分だけ扱う。
- 読者を引きつける目的だけの問いかけや Before/After 演出は避ける。
- 既存の公開記事を改稿するときは、公開済みの事実関係を変える根拠と影響を確認する。

## 完了条件

- 主要な事実に出典があり、リンク先が主張を直接支えている。
- 異なる実践がある論点では、選択条件を説明している。
- 記事の Front Matter と Markdown lint が通る。
